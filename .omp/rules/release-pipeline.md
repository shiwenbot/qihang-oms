# 发版纪律（qihang-oms）

## 为什么有这些规矩（2026-08 真实事故，勿重蹈）

1. **同一份源码，不同电脑表现不同**：菜单存在数据库 `sys_menu` 里而非代码里；旧流程靠手工导出的快照建库 + 手工执行增量 SQL，开发机"正常"依赖了本地库的手工状态，用户全新安装后缺"AI生图"菜单、默认密码错乱。教训：**任何机器的效果都不允许依赖手工步骤**。
2. **非幂等 SQL 会清用户数据**：旧版 ai_image.sql 开头 `DROP TABLE`——若每次启动执行等于反复清空用户生图历史；裸 `ALTER` 第二次启动直接报错起不来。教训：**增量脚本必须幂等且不许靠 DROP/重建**。
3. **手工打包产物漂移**：手工 npm build → 手工拷 dist → 手工 mvn → 手工组装，任何一步漏做或模板目录状态不同，各机器产物就不同。教训：**打包只能走脚本**。
4. **过期文案误导排查**：启动横幅写着"密码 admin"，实际种子是别的——排查一小时。教训：**改默认密码必须五处同步**（种子哈希、reset 脚本、根 README、包内 README.txt、启动横幅）。

## 纪律

1. 发版/打包**只能**用 `package/windows/Build-Package.ps1`；禁止手工组装，禁止 `-SkipTest` 强行发版（门禁模拟的就是用户电脑全新首装）。
2. 数据库变更唯一入口 `docs/sql/`（幂等范式见 `rule://sql-idempotency`）；禁止只改 `docs/qihang-oms.sql` 快照（老安装永不重导）；禁止往 `Start-QihangOms.ps1` 加单脚本特例。
3. 用户安装约定：解压覆盖原目录、**绝不删 `runtime\`**、先停后启。
4. 改动发版链路前先读仓库根 `AGENTS.md` 的文件地图。
